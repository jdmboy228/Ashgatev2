# Ashgate

Ashgate 0.7.5 — открытая замена Proxifier для Windows 10/11 x64. Вы выбираете
приложения по имени exe или полному пути, и их TCP, UDP (если прокси умеет UDP)
и DNS уходят в настроенный прокси, идут напрямую или отбрасываются. Остальные
приложения не настраиваются и ходят в сеть напрямую. Само приложение
проксировать не нужно: у него нет параметра прокси, сокс-порта и переменных
окружения. Прокси — SOCKS5, HTTP CONNECT или VLESS. Для VLESS отдельный
клиент вроде v2rayN не нужен: Ashgate поднимает его сам.

Код Ashgate распространяется по MIT. Драйвер WinDivert и встроенный Xray-core
лицензированы иначе, см. `THIRD_PARTY_NOTICES.md`.

## Почему WinDivert

Перехват «только эти процессы» на Windows нельзя сделать из пользовательского
режима без драйвера. Рассмотрены три готовых основы. Код Proxifier, ProxiFyre и
sing-box не копировался.

| Основа | Подпись драйвера | Лицензия | TCP и UDP по процессу | Почему не взята как основа |
| --- | --- | --- | --- | --- |
| [WinDivert 2.2.2](https://reqrypt.org/windivert-doc.html) | Официальный `WinDivert64.sys` уже подписан (варианты A/B/C отличаются подписью, не кодом). Тестовый режим Windows не нужен. | LGPL-3.0 или GPL-2.0. Ashgate только загружает немодифицированную DLL. | Да: слой SOCKET/FLOW даёт PID, слой NETWORK переписывает пакеты. | Выбрана. |
| [Windows Packet Filter](https://www.ntkernel.com/) и [ProxiFyre](https://github.com/wiresock/proxifyre) | Драйвер NDIS подписан у вендора. | ProxiFyre — AGPL-3.0. Бесплатная лицензия Windows Packet Filter запрещает коммерческое распространение; разработческая лицензия платная. | ProxiFyre уже умеет SOCKS5 на процесс. | Лицензия драйвера не разрешающая. |
| [sing-box](https://sing-box.sagernet.org/) TUN или tun2socks + wintun | wintun подписан. | sing-box — GPL-3.0. | `process_name` / `process_path` есть, но TUN забирает трафик всей системы. Чужие приложения пересылает уже sing-box, а не стек Windows. DNS при `strict_route` тоже системный. | Нарушает требование «остальные приложения не трогать». |

WinDivert 2.2.2 ставится сам при первом `WinDivertOpen`: отдельные установщик и
test-signing не нужны. Нужны права администратора. Второе окно не запускается:
уже работающий Ashgate выходит на передний план. «Выход» в трее останавливает
перехват, локальные мосты VLESS и завершает процесс. На части машин с HVCI,
политикой уязвимых драйверов или антивирусом загрузка может закончиться кодом
1275; тогда имеет смысл скачать вариант подписи B или C с той же страницы релизов.

## Как это устроено

1. Слой SOCKET (события BIND, CONNECT, ACCEPT, CLOSE) и слой FLOW (ESTABLISHED)
   запоминают, какому PID принадлежит локальный адрес и порт. Имя exe читается
   через `QueryFullProcessImageName`. Если событие ещё не пришло, используется
   таблица IP Helper (`GetExtendedTcpTable` / `GetExtendedUdpTable`).
2. Слой NETWORK с фильтром `outbound and !impostor and (tcp or udp)` видит
   исходящие пакеты. Пакет без подходящего правила отправляется обратно с тем
   же адресом WinDivert, который вернул `WinDivertRecv`: TTL и флаги разгрузки
   контрольных сумм не меняются. Один и тот же handle свой пакет повторно не
   забирает.
3. TCP выбранного процесса переписывается в локальный NAT. SYN с адресом
   приложения уходит на `127.0.0.1:34010` или `[::1]:34010` с подставным
   исходным портом. Ответ слушателя переписывается обратно: источник — настоящий
   сервер, назначение — приложение, направление inbound, индекс интерфейса
   исходного пакета. Дальше Ashgate открывает SOCKS5 или HTTP CONNECT и
   склеивает потоки. Уже установленное соединение без SYN не проксируется.
4. UDP в ядро не заворачивается. Исходный пакет отбрасывается, полезная
   нагрузка уходит в SOCKS5 UDP ASSOCIATE, ответ собирается заново так, будто
   его прислал исходный сервер. VLESS для правил выглядит так же: внутри
   процесса поднимается локальный SOCKS5, а наружу уходит VLESS. У HTTP-прокси
   общего UDP нет: порт 53 уходит как DNS-over-TCP через CONNECT, остальной
   UDP по умолчанию блокируется (`udpUnsupported: direct` отправит его мимо
   прокси).
5. DNS. В режиме `proxy` (по умолчанию) запросы на порт 53 выбранного
   приложения уходят на `1.1.1.1:53` и `8.8.8.8:53` через прокси правила.
   Режим `original` сохраняет сервер, который выбрало приложение, но всё равно
   через прокси. Системный клиент DNS живёт в `svchost.exe`, и WinDivert не
   может отнести его запрос к Chrome или curl. Поэтому `getaddrinfo` может
   утечь мимо прокси. `dns.includeSystemResolver` заворачивает только порт 53
   у `svchost.exe` в указанный прокси; это влияет на DNS всех приложений.
   Правило на `svchost.exe` конфигурация отклоняет. Внедрения DLL нет.

В обход всегда идут loopback, multicast, broadcast, link-local
(`169.254.0.0/16`, `fe80::/10`) и адреса самих прокси, иначе соединение с
прокси зациклится. `bypassPrivate` (по умолчанию выключен) добавляет RFC1918 и
`fc00::/7`. Свой процесс Ashgate тоже не проксируется.

## Сборка

Нужен Go 1.25 или новее: встроенный Xray-core v1.250803.0 собирается этой
версией. Кросс-компиляция с Linux:

```sh
bash scripts/package.sh
```

Скрипт скачивает WinDivert 2.2.2-A, по возможности вшивает манифест
(права администратора, Common Controls 6, DPI) и кладёт в `dist/`:

- `ashgate.exe`
- `WinDivert.dll`
- `WinDivert64.sys`
- `ashgate-0.5.2-windows-amd64.zip` (то же содержимое дублируется в
  `ashgate-windows-amd64.zip`)

Только бинарник, без драйвера:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath \
  -ldflags "-s -w -H windowsgui" -o dist/ashgate.exe ./cmd/ashgate
```

На Windows то же самое делает `scripts/package.ps1` (PowerShell). Либо вручную:

```powershell
go test ./...
$env:CGO_ENABLED = "0"
go build -trimpath -ldflags "-s -w -H windowsgui" -o dist\ashgate.exe .\cmd\ashgate
```

`WinDivert.dll` и `WinDivert64.sys` из каталога `x64` архива
[WinDivert-2.2.2-A.zip](https://github.com/basil00/WinDivert/releases/download/v2.2.2/WinDivert-2.2.2-A.zip)
должны лежать в той же папке, что и `ashgate.exe`. DLL ищет sys рядом с собой.

GitHub Actions (`.github/workflows/build.yml`) гоняет тесты на Ubuntu и
собирает zip на `windows-latest`. Отдельная Ubuntu-сборка проверяет
кросс-компиляцию.

Тесты, которым не нужен Windows:

```sh
go test -race ./...
```

Они покрывают разбор JSON, сопоставление правил, рукопожатие SOCKS5 (в том
числе с паролем и UDP ASSOCIATE), HTTP CONNECT, DNS-over-TCP, перепись
пакетов и локальный TCP/UDP-релей движка.

## Обновление

«Настройки → О программе → Обновления → Проверить» сравнивает версию с
`version.json` в корне репозитория на GitHub. Если есть новее, кнопка
«Скачать» открывает страницу релизов в браузере; установщик поверх
установленной версии сохраняет настройки.

Проще всего — дважды щёлкнуть `update.bat` в корне клона. Он спросит права
администратора, скачает свежий код (`git pull`), соберёт новый `ashgate.exe` в
`build\update`, закроет запущенный Ashgate так же, как «Выход» (`ashgate quit`),
заменит exe в той папке, откуда он работал (или из задачи автозапуска, службы,
иначе в `dist\`), и запустит его снова. Если перехват был включён, он включится
сам. Если сборка не удалась, установленная версия не трогается; прежний exe
остаётся рядом как `ashgate.old.exe`. Нужны Go 1.25+ и Git. Другая папка:
`update.bat "C:\Apps\Ashgate"`. Версии, которые не знают `ashgate quit`,
`update.bat` завершает принудительно, и перехват после обновления нужно
включить вручную.

Вручную: `git pull` обновляет только исходный код. Чтобы изменения появились:

1. Закройте Ashgate: трей → «Выход». Пока старая копия запущена, новый exe
   только выводит её окно на передний план.
2. Пересоберите: `powershell -ExecutionPolicy Bypass -File scripts\package.ps1`
   из папки `ashgate-src` (нужен Go и git). Готовый exe — `dist\ashgate.exe`.
3. Запустите `dist\ashgate.exe` и откройте «Настройки → О программе»: коммит
   должен совпадать с последним на GitHub.

## Установка

Установщик `Setup.exe` ставит Ashgate в `Program Files` (нужны права
администратора: файлы программы, которая работает от администратора, не
должны быть доступны для записи обычным программам), создаёт ярлык в меню
«Пуск» и закрывает запущенную копию перед обновлением. При удалении он
снимает правила kill switch в брандмауэре и задачу автозапуска; настройки в
`%ProgramData%\Ashgate` остаются. Собрать его: `build-installer.ps1` в корне
репозитория (нужны Go и Inno Setup 6.3+), результат — `ashgate-src\dist\Setup.exe`.
Перед сборкой версия в `version.json` должна совпадать с
`internal\version\version.go`.

Без установщика:

1. Распакуйте zip. Не разделяйте exe, dll и sys.
2. Запустите `ashgate.exe`. Появится запрос UAC. Без администратора драйвер не
   загрузится: WinDivert вернёт код 5.
3. Первый запуск регистрирует и загружает подписанный драйвер. Отдельного
   установщика нет. Когда последний handle закрывается, фильтр обычно
   выгружается.
4. Если Windows отвечает кодом 577, подпись отклонена. Код 1275 — драйвер
   заблокирован политикой или антивирусом. Код 1753 — выключена служба Base
   Filtering Engine. Код 654 — уже загружена другая сборка WinDivert.
   Текст ошибки показывается в окне и пишется в журнал.

Автозапуск из окна — задача планировщика, не служба: при входе в систему
открывается окно и включается перехват. Старую службу `Ashgate` окно
останавливает и удаляет само. Команда `run` по-прежнему запускает движок без
окна. Службу можно поставить только вручную, если окно не нужно:

```text
ashgate service install
ashgate service start
ashgate service stop
ashgate service uninstall
```

Служба называется `Ashgate`, отображаемое имя — Ashgate Transparent Proxy,
запуск автоматический. В её командную строку записывается `run -config <путь>`.
После правки JSON службу нужно перезапустить: она не перечитывает файл сама.

## Окно

Окно тёмное, в стиле Windows 11 с оранжевым акцентом Ashgate: своя шапка без
системной полосы сверху, слева узкая полоса значков с подписями —
«Приложения», «Прокси», «Журнал» (страница «Подключения»), внизу
«Настройки» и круглая кнопка «Запустить»/«Стоп»; под ней точка состояния, в
подсказке — число потоков и трафик. Шрифт — системный Segoe UI Variable,
значки — Fluent. Светлой темы нет. Окно открывается на «Приложениях»; пока
прокси нет — на «Прокси». Размер
меняется за любой край, в том числе за верхний. Закрытие и сворачивание прячут
окно в трей. Меню трея: «Открыть», «Старт» или «Стоп», «Выход».

Страница прокси добавляет SOCKS5, HTTP и VLESS, правит запись и проверяет
сервер кнопкой «Проверить» (TCP до 1.1.1.1:443; для SOCKS5 и VLESS ещё UDP
ASSOCIATE). Результат в конфиг не пишется. У SOCKS5 и HTTP поля такие: имя,
тип, адрес `хост:порт`, необязательные логин и пароль. Пароль хранится в JSON
открытым текстом, файл пишется с правами только для текущего пользователя
(0600), но администратор его прочитает.

Приложения (бывшие правила) идут сверху вниз: первое включённое совпадение
побеждает. В строке — номер, иконка exe на Windows, имя без `.exe`. Путь в
строке не показывается, его копирует пункт «Скопировать путь». Порядок меняется
перетаскиванием. Правки копятся локально: панель «N несохранённых изменений»,
кнопка «Сохранить» или Ctrl+S. «Отменить» возвращает последний сохранённый
список. Действие — `proxy`, `direct` («напрямую») или `block`
(«блокировать»: пакеты этого приложения отбрасываются). У `direct` и `block`
поле `proxy` пустое. Процесс — либо `curl.exe` (без пути, без учёта регистра),
либо полный путь. «Обзор…» открывает выбор exe, отдельный список показывает уже
запущенные приложения. Приложение можно выключить, не удаляя.

«Подключения» — живой журнал. Фильтр по процессу, адресу и прокси, переключатель
Все/TCP/UDP, «Только ошибки», пауза и очистка экрана. Пауза считает новые
соединения, которые не показаны. Ошибка раскрывается в строке: её можно
скопировать и перейти к приложению. Очистка не трогает файл журнала. Журнал
также дописывается в `ashgate.log` рядом с конфигурацией, если в JSON не задан
`log.file`.

«Настройки» пишутся сразу, без кнопки «Сохранить»: DNS через прокси или как
выбрало приложение, список DNS-серверов, системный резолвер (`svchost.exe`,
влияет на DNS всех программ), судьба UDP, который HTTP-прокси не умеет
(`block` или `direct`), обход частных сетей (`bypassPrivate`, включая
`fc00::/7`), автозапуск и подробный журнал. «Запускать с Windows» — задача
планировщика на вход текущего пользователя, не поле в JSON и не служба:
окно открывается и перехват включается. Выключение удаляет задачу.
«Подробный журнал» сохраняет `log.level`
`debug` вместо `info`. Сам журнал соединений при обоих уровнях один и тот же.

Окно рисуется через WebView2. Среда выполнения уже есть в Windows 10/11 с
новым Edge. Если её нет, Ashgate показывает, куда её поставить:
https://developer.microsoft.com/microsoft-edge/webview2/ . Рядом с exe по-прежнему
нужны только `WinDivert.dll` и `WinDivert64.sys`.

## Конфигурация

По умолчанию файл такой:

- `%ProgramData%\Ashgate\config.json`, если каталог доступен на запись;
- иначе `%AppData%\Ashgate\config.json`.

Пример — `configs/ashgate.example.json`. Правило `curl.exe` в примере
выключено, чтобы первый запуск ничего не перехватывал.

```json
{
  "version": 1,
  "relay": { "tcp4": "127.0.0.1:34010", "tcp6": "[::1]:34010" },
  "dns": {
    "mode": "proxy",
    "servers": ["1.1.1.1:53", "8.8.8.8:53"],
    "includeSystemResolver": false,
    "systemResolverProxy": ""
  },
  "bypassPrivate": false,
  "udpUnsupported": "block",
  "log": { "file": "", "level": "info" },
  "proxies": [
    { "name": "local", "type": "socks5", "address": "127.0.0.1:1080", "username": "", "password": "" }
  ],
  "rules": [
    { "enabled": true, "process": "curl.exe", "action": "proxy", "proxy": "local" }
  ]
}
```

`action` равен `proxy`, `direct` или `block`. У `direct` и `block` поле `proxy`
пустое. Правило распространяется на дочерние процессы приложения на любой
глубине (помощники, обновления, игры из лаунчера): у них нет своего правила —
действует правило ближайшего предка. `"children": false` это отключает. Через
`explorer.exe`, `svchost.exe` и другие системные процессы правило не
наследуется. Имя без расширения (`chrome`) значит `chrome.exe`.

`killSwitch` у правила включает или выключает kill switch только для него;
без поля действует общий `killSwitch`. `tcpOnly: true` отбрасывает UDP
приложения (QUIC перейдёт на TCP через прокси), DNS при этом идёт через
прокси. В `process` можно писать маску: `*` — любые символы, включая `\`,
например `*\Discord\app-*\Discord.exe`.

Группы: `"groups": [{ "name": "Мессенджеры", "enabled": true, "action":
"proxy", "proxy": "aeza", "collapsed": false }]` и `"group": "Мессенджеры"` у
правил. Тумблер и маршрут группы действуют на все её правила; порядок
проверки — по-прежнему порядок правил в файле.

`killSwitch: true` включает kill switch. Пока идёт перехват, приложения с
правилом `proxy` (и их дочерние процессы) не выходят в сеть напрямую: открытое
до «Старт» соединение сбрасывается, чтобы приложение переподключилось через
прокси, а UDP, который прокси не умеет, блокируется даже при
`udpUnsupported: direct`. Пока перехват выключен или Ashgate закрыт, эти
программы блокирует Брандмауэр Windows (правила «Ashgate kill switch», вход и
выход). На время перехвата правила снимаются: Windows проверяет брандмауэр при
подключении, раньше, чем Ashgate перенаправит пакет. Если Ashgate упадёт во
время перехвата, правила вернёт отдельный процесс-сторож. Для правила по имени
exe ищется среди запущенных и установленных программ; ненайденные окно
перечисляет на главной. `dns.mode` равен `proxy` или `original`. `udpUnsupported` равен `block`
или `direct`. `log.level` равен `info` или `debug`. `ui.theme` — необязательное
поле `dark` или `light`; пустое значение значит тёмную тему. Файл версии 1 без
`ui` открывается как раньше. Имена прокси — буквы, цифры, `_`, `.`, `-`.

Тип прокси — `socks5`, `http` или `vless`. Записи SOCKS5 и HTTP не менялись.
У VLESS адрес — это `хост:порт` сервера (он же исключается из перехвата, чтобы
не было петли). Рядом лежит исходная ссылка `link` и разобранный объект
`vless`. Случайный адрес моста в файл не пишется. Если задан `socksPort`,
мост публикуется на `127.0.0.1:socksPort` (SOCKS5, UDP ASSOCIATE) и на
следующем порту как HTTP. `localUser` и `localPass` — необязательный логин
этого локального входа. Пустой `socksPort` оставляет случайный порт только
для правил Ashgate.

```json
{
  "name": "aeza",
  "type": "vless",
  "address": "203.0.113.10:443",
  "link": "vless://uuid@203.0.113.10:443?type=xhttp&security=reality&sni=www.microsoft.com&fp=chrome&pbk=...&sid=ab#aeza",
  "vless": {
    "uuid": "b7e2c1a0-4f3a-4c2b-9a11-111111111111",
    "network": "xhttp",
    "security": "reality",
    "sni": "www.microsoft.com",
    "fp": "chrome",
    "pbk": "...",
    "sid": "ab",
    "path": "/",
    "mode": "auto"
  }
}
```

Если в файле есть только `link`, а `vless` пустой, Ashgate разбирает ссылку при
загрузке. Если оба заполнены, берётся объект `vless` (так сохраняются ручные
правки). Поддерживаются транспорты `tcp`, `xhttp`, `ws`, `grpc`, `httpupgrade`
и защита `reality`, `tls`, `none`. Flow `xtls-rprx-vision` используется только
с TCP: на XHTTP, WS и gRPC он отбрасывается, даже если панель вписала его в
ссылку.

## VLESS из 3x-ui

На VPS (панель 3x-ui) создайте inbound VLESS. Для сетей, где обычный
VLESS+TCP+REALITY уже режут, берите транспорт XHTTP и безопасность REALITY.
Также подходят TCP+REALITY с flow `xtls-rprx-vision`, gRPC+REALITY и
WS, XHTTP или gRPC поверх TLS.

1. В 3x-ui откройте клиента inbound и скопируйте ссылку `vless://…` (то же
   меню, что отдаёт ссылку в v2rayN).
2. В Ashgate: «Прокси» → «Прокси +» → тип **VLESS** → вставьте ссылку в поле
   «Вставить ссылку» → «Разобрать».
3. Проверьте адрес, UUID, транспорт, SNI, публичный ключ, short id, path и
   mode. Имя можно оставить из фрагмента после `#` или вписать своё (латиница,
   цифры, `_`, `.`, `-`).
4. «Проверить» открывает соединение через этот сервер до `1.1.1.1:443` и
   показывает задержку. Для VLESS также проверяется UDP.
5. «ОК», затем правило на нужный exe с действием «прокси» и этим именем.
   «Старт». Отдельный v2rayN не запускайте: тот же локальный порт ему не нужен,
   а два клиента на один UUID обычно и так работают, но трафик пойдёт через
   Ashgate.

Если ссылка битая, в окне будет «Не удалось разобрать ссылку VLESS». Если ключ,
short id или SNI не сходятся с панелью, в журнале соединений — «REALITY:
рукопожатие не удалось. Проверьте публичный ключ, short id и SNI». Если сервер
молчит — «VLESS: нет ответа от сервера (таймаут)». Если порт закрыт — «VLESS:
сервер отклонил соединение».

## VLESS в Dolphin{anty} / других приложениях

Профиль Dolphin{anty} умеет HTTP, SOCKS5 и SSH, но не VLESS. Ashgate
публикует каждый VLESS как обычный SOCKS5 на localhost, и профиль ходит в
него напрямую.

1. В диалоге VLESS заполните «Локальный SOCKS5-порт», например `10808`.
   Пустое поле — прежнее поведение, случайный порт только для правил.
2. Сохраните. Пока открыто окно Ashgate или запущена служба, на
   `127.0.0.1:10808` слушает SOCKS5 (с UDP), а на `127.0.0.1:10809` — HTTP.
   Кнопка «Старт» для этого не нужна: порт есть и когда перехват остановлен.
   В списке прокси у строки стоит «слушает»; адрес копируется кнопкой.
   Служба публикует порт, пока она запущена (служба сразу включает и перехват).
3. В профиле Dolphin укажите SOCKS5 `127.0.0.1` и этот порт (или HTTP и
   следующий порт). Логин заполняйте, только если задали его в Ashgate.
4. Правило Ashgate на `dolphin.exe` / процесс антидетекта **не добавляйте**.
   Профиль сам выбирает прокси. Соединения на `127.0.0.1` Ashgate не
   перехватывает, а исходящий трафик моста к VPS идёт от процесса Ashgate и
   тоже не попадает в правила. Если правило на Dolphin всё же есть, петли на
   локальный порт не будет, но остальной трафик этого exe (другие профили,
   обновления) уйдёт в прокси правила — обычно это не то, что нужно.

Порт занят только на `127.0.0.1`, в локальную сеть он не открывается. Если
номер уже занят, сохранение покажет «VLESS: порт … занят. Выберите другой
локальный SOCKS5-порт», та же строка попадёт в журнал. Два VLESS не могут
делить один порт; HTTP-порт (номер + 1) тоже не должен совпасть с чужим.

Xray-core вшит в `ashgate.exe` (MPL-2.0). Рядом с exe по-прежнему только
`WinDivert.dll` и `WinDivert64.sys`.

Проверка без запуска драйвера: `ashgate check -config путь`.

Команды:

```text
ashgate [--autostart] [-config файл]
ashgate gui [--autostart] [-config файл]
ashgate run [-config файл]
ashgate check [-config файл]
ashgate service install|uninstall|start|stop [-config файл]
ashgate version
```

`run` держит консоль и останавливается по Ctrl+C. Одновременно может работать
только один движок (мьютекс `Global\AshgateEngine`).

## Окно

Первый запуск открывает окно 1100×720 логических пикселей (DIP), но не больше
рабочей области монитора минус 32. Тянуть меньше 760×520 нельзя: минимум
считается в `WM_GETMINMAXINFO` с DPI окна, а не через `SetSize(HintMin)` —
тот принимает физические пиксели и на 150% дал бы окно около 507×347.
Верхнего предела у перетаскивания нет. Толстая рамка остаётся неклиентской:
WebView2 занимает только клиент, и края тянутся как в 0.3.1. Развёрнутое
окно ставится в рабочую область и не закрывает панель задач. В `ashgate.log`
при старте есть строка `dpi=… min=… maxTrack=none`.
Закрытие прячет окно в трей и записывает положение и размер в `window.json`
рядом с конфигом (в сам `config.json` размер не пишется, версия конфига
остаётся 1).

Ниже 920 px сайдбар становится рейкой иконок: подпись всплывает при наведении
и фокусе с клавиатуры. Таблицы прячут второстепенные колонки по ширине
страницы и прокручиваются только внутри себя. У диалога скроллится тело,
заголовок и кнопки «Добавить» / «Сохранить» и «Отмена» остаются на экране. Порядок приложения, когда
маркер перетаскивания скрыт, меняется пунктами «Выше» и «Ниже» в меню строки.

Масштаб страницы WebView2 (Ctrl+колесо, Ctrl±) оставлен включённым. Вёрстка
держит окно до 640×440 CSS-пикселей — это примерно 120% при минимуме
760×520. Отдельный COM-вызов `put_IsZoomControlEnabled` не используется:
в go-webview2 его нет, а ошибка в vtable на Windows отсюда не проверяется.

## Проверка на Windows

Движок 0.1.0 уже прогнан на настоящей Windows 10/11: Telegram через HTTP-прокси
ходит, а оставшиеся ответы 502 отдавал сам прокси. Сборка 0.3.0 на том же
компьютере прогнала VLESS+XHTTP+REALITY через VPS Aéza (3x-ui). 0.3.1 не
меняет этот путь перехвата. Фиксированный локальный SOCKS5 проверялся на
Linux: `curl --socks5-hostname 127.0.0.1:10808` через локальный Xray VLESS,
рядом HTTP на 10809 и UDP ASSOCIATE. Окно 0.3.3 сжимается до 760×520;
интерфейс 0.5.0 эту рамку не меняет. Нативный минимум, DPI, панель задач при
разворачивании и трей на Windows здесь не запускались. Интеграция
Dolphin{anty} из 0.4.x отложена и лежит в ветке `dolphin-0.4` (тег `v0.4.2`).
Лишние поля такого конфига, включая блок Dolphin, при открытии 0.5.0
сохраняются. Ниже сценарий для
Windows 10 или 11 x64 от администратора.

1. Поднимите SOCKS5, который вы контролируете. Для TCP достаточно
   `ssh -D 1080 -N user@server`. У `ssh -D` обычно нет UDP ASSOCIATE; для UDP
   нужен Dante, 3proxy или sing-box.
2. Соберите zip или возьмите артефакт CI. Положите `ashgate.exe`,
   `WinDivert.dll` и `WinDivert64.sys` в один каталог.
3. Запустите `ashgate.exe`, подтвердите UAC.
4. Добавьте прокси `local`, тип `socks5`, адрес `127.0.0.1:1080`.
5. Добавьте правило `curl.exe` → прокси `local`, включите его, нажмите «Старт».
6. В другом окне, тем же пользователем:

   ```text
   curl.exe https://api.ipify.org
   ```

   Должен вернуться адрес выхода прокси, не адрес машины. В журнале Ashgate
   есть строка `curl.exe` / TCP. В журнале самого прокси видно входящее
   соединение от Ashgate.
7. Контроль, что остальные приложения не трогаются. `powershell.exe` в
   правилах нет:

   ```text
   powershell -Command "(Invoke-WebRequest -UseBasicParsing https://api.ipify.org).Content"
   ```

   Должен вернуться обычный внешний адрес машины (если у Windows нет своего
   системного прокси).
8. Выключите правило или нажмите «Стоп». Повторите `curl.exe`: адрес снова
   свой.
9. HTTP CONNECT: смените тип прокси на `http` и укажите HTTP-прокси.
   `curl.exe https://api.ipify.org` идёт через CONNECT. QUIC при этом
   блокируется, и curl остаётся на TCP.
10. DNS самого приложения. `nslookup.exe` шлёт UDP/53 сам, не через svchost.
    Добавьте правило `nslookup.exe` на SOCKS5 с UDP и выполните
    `nslookup example.com 1.1.1.1`. В журнале — UDP к DNS-серверу со статусом
    «открыто». На машине без прокси этого запроса на проводе быть не должно:
    он уходит внутри SOCKS. Системный `curl.exe` на Windows обычно резолвит имя
    через `svchost.exe`. Этот запрос в журнал curl не попадёт, пока не включён
    `dns.includeSystemResolver`. Включайте его, только если готовы отправить в
    прокси DNS всех программ.
11. UDP. На SOCKS5 с UDP ASSOCIATE добавьте правило `python.exe` и выполните
    короткий `socket.sendto` на `1.1.1.1:53`. В журнале — UDP `python.exe`.
    Если сервер UDP не умеет, статус будет «ошибка», а не тихий обход.
12. VLESS. Вставьте ссылку из 3x-ui, как в разделе «VLESS из 3x-ui». Правило
    `curl.exe` → этот прокси. `curl.exe https://api.ipify.org` должен вернуть
    адрес VPS. В журнале — `curl.exe` / TCP / имя прокси. QUIC (UDP/443) у
    VLESS тоже уходит в мост, а не блокируется как у HTTP.

Если «Старт» сразу показывает ошибку WinDivert, в сообщении есть код. Чаще
всего это отсутствие dll/sys рядом с exe (код 2) или запуск без
администратора (код 5).

## Ограничения

- Пакеты всех приложений ненадолго проходят через процесс Ashgate. Чужие пакеты
  возвращаются без изменения адресов. Это не «нулевая» задержка.
- TCP проксируется только с SYN. Уже открытый сокет останется прямым, пока
  приложение не переподключится (с kill switch он сбрасывается).
- Дочерний процесс наследует правило, только если родитель был жив, когда
  Ashgate впервые увидел ребёнка. Игра, чей лаунчер уже завершился, правило
  лаунчера не получит — дайте ей своё правило.
- Kill switch при выключенном перехвате блокирует только программы с известным
  путём к exe и те дочерние процессы, что запущены в этот момент. Брандмауэр
  Windows должен быть включён. В режиме `ashgate run` и службы работает только
  часть kill switch внутри перехвата.
- Фрагменты по умолчанию WinDivert не отдаёт в фильтр. Редкие фрагментированные
  пакеты могут уйти мимо правил. Windows обычно ставит DF.
- Фрагментированный пакет проксируемого или блокируемого потока отбрасывается
  целиком: первый фрагмент и все следующие с тем же идентификатором.
- HTTP-прокси не перевозит произвольный UDP. По умолчанию такой UDP
  блокируется, чтобы QUIC не обошёл прокси.
- `includeSystemResolver` влияет на DNS всей системы, не только выбранных
  приложений.
- Loopback, multicast, broadcast и link-local не проксируются. Частные сети
  проксируются, пока не включён `bypassPrivate`.
- Ответ, собранный Ashgate, помечается как impostor. WinDivert уменьшает у
  такого пакета TTL на единицу. Обычные пакеты других приложений это не
  затрагивает.
- Один движок на машину. Окно и служба не должны захватывать трафик
  одновременно. Правка JSON из окна не применяется к уже запущенной службе.
- Пароли лежат в JSON открытым текстом.
- Прокси должен быть достижим напрямую. Его адрес автоматически исключается из
  перехвата.
- Движок 0.1.0 и VLESS 0.3.0 (XHTTP+REALITY, VPS Aéza) на Windows уже
  подтверждены. Окно 0.5.0, трей, выбор файла, список процессов и публикация
  порта до «Старт» на этой машине не запускались: минимум окна и DPI заданы
  кодом 0.3.3 и не менялись. Профиль Dolphin{anty} в эту сборку не входит.
  Разбор `vless://`, локальный мост, фиксированный `127.0.0.1:10808` и обмен
  через Xray на Linux покрыты тестами. Юнит-тесты гоняются без WinDivert и
  без WebView2.
