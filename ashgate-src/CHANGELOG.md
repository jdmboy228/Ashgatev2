# История изменений

## 0.9.3

Скорость VLESS, без потерь пакетов, оставшиеся пути к настоящему адресу,
ошибки окна.

Скорость и потери:

- VLESS TCP идёт в Xray внутри процесса, без второго соединения через
  локальный SOCKS5 и его рукопожатия: каждый пакет проходит перехват вдвое
  реже.
- Перехват читает и отправляет пакеты пачками (до 64 за вызов WinDivert),
  а не по одному. Очередь драйвера — 16384 пакета и 32 МБ; события сокетов
  при всплеске соединений не теряются.
- Трафик на loopback больше не проходит через Ashgate, кроме ответов
  приёмника: локальные соединения программ не замедляются.
- Потери UDP: ответы VLESS (QUIC, видео, звонки) отбрасывались, когда
  в очереди Xray было больше 16 пакетов. Теперь Xray ждёт, а не теряет.
  Исходящий UDP раскладывается по четырём очередям по потоку: порядок
  пакетов одного потока сохраняется. Переполнение пишется в журнал одной
  строкой в секунду, а не строкой на пакет. Ошибка одного ответа больше не
  обрывает поток.
- К одному серверу VLESS одновременно идёт до 8 рукопожатий (было 2), после
  сбоя — 2, пока сервер не ответит. Страницы с десятками соединений по RAW
  открываются без очереди.
- Буферы реле 64 КБ, контрольные суммы считаются в 3–7 раз быстрее, запись
  журнала на диск идёт в фоне и не задерживает пакеты.
- Чтение таблиц соединений Windows больше не останавливает обработку
  пакетов: оно идёт в фоне.
- Xray закрывал соединение, молчащее 5 минут (SSH, IMAP IDLE); теперь —
  30 минут. После того как одна сторона закончила передачу, вторая получает
  5 секунд тишины вместо 1: медленный ответ на полузакрытое соединение не
  обрывается.
- Переключение серверов подписки: если соединения через активный сервер
  остаются без ответа (3 за 20 секунд), проверка идёт сразу, а не по
  таймеру раз в минуту.

Утечки:

- Утечка: адреса прокси-серверов шли мимо туннеля у всех программ. Если
  сервер VLESS за CDN, сайт на том же IP CDN видел настоящий адрес. Теперь
  программа с правилом идёт к этому IP по своему правилу; напрямую к
  IP:порту сервера уходит только соединение, чью программу не удалось
  узнать.
- Утечка: пакет новой связи (SYN, UDP), чью программу не удалось узнать за
  50 мс или когда в очереди ожидания было 256 пакетов, уходил напрямую.
  При любом правиле через прокси он теперь отбрасывается, повтор решается
  заново; в журнале — «программа не определена: пакеты отброшены (N)».
  Ожидающих пакетов теперь до 2048, при переполнении решается только самый
  старый. Неразборчивый пакет при таких правилах тоже отбрасывается.
- Утечка: новый сокет программы с правилом мог занять порт, который только
  что закрыла программа без правила, и получить её решение «напрямую» — по
  записи о закрытом сокете или по кэшу UDP. Для новых связей закрытые
  сокеты и устаревшие таблицы Windows больше не учитываются, а закрытие
  UDP-сокета сбрасывает кэш его порта.
- System (PID 4) и защищённые процессы, чьё имя не читается, определяются
  как известные: их трафик не ждёт 50 мс и не отбрасывается.
- Утечка: фрагменты проксируемого TCP после первого уходили к сайту
  с настоящим адресом. Теперь отбрасывается весь пакет.
- Утечка: если `[::1]:34010` занят, IPv6 TCP программ с правилом уходил
  этой программе. Теперь он отбрасывается, программы переходят на IPv4.
- Утечка: шифрованный DNS службы Windows (DoT, DoH к известным резолверам)
  шёл напрямую. Теперь — через тот же прокси, что и её обычный DNS.
- После сбоя перехвата правила kill switch ставятся сразу, до остановки
  драйвера, а не через несколько секунд.
- Зоны `.ru`, `.рф`, `.su` — теперь обычные строки списка «Напрямую, без
  VLESS»: по умолчанию напрямую, но их можно удалить, и они не вернутся.
  Старые настройки получают их один раз. Кириллические домены пишутся как
  есть (`госуслуги.рф`).
- Токен окна принимается только в заголовке (в адресе — лишь для значков),
  запросы к API — только JSON и только со своей страницы. Ссылку или файл
  нельзя перетащить в окно: чужая страница не получит токен.
- Файлы состояния (kill switch, окно, кэш DoH, задача автозапуска) пишутся
  заново, а не поверх подложенного файла; XML задачи — в защищённую папку
  настроек, не во `%TEMP%`. `update.bat` запускает git без хуков.

Окно:

- «Добавить приложение»: выбор из списка, «Обзор…», готовые группы и
  найденный путь к exe теперь заполняют поле (с 0.9.1 они стирались).
- Прокси не сохранялся после переключения через тип «Подписка»; кнопка
  типа у сохранённой подписки ломала сохранение.
- Изменения настроек терялись при переходе на другую вкладку, набранный
  текст — всегда. Настройки показывают сохранённые значения после отказа.
- «Сохранено, но не применено» больше не выглядит как ошибка сохранения;
  занятый порт VLESS не превращает каждое сохранение в окно с ошибкой.
- Результаты проверки и разбора ссылки не попадают в другой диалог и не
  стирают набранный текст; проверка черновика не перезаписывает статус
  сохранённого прокси.
- Кнопки «Старт/Стоп» и «Проверить все» неактивны, пока идёт запрос.
- Окно обновляется и при открытом диалоге; ошибка запуска из трея или
  автозапуска видна, пока её не закроют; потеря связи с Ashgate видна.
- Выделение правил сбрасывается после перемещения групп; меню с клавиатуры
  открываются у кнопки; пароль SOCKS не показывается открытым текстом;
  длинный текст переносится.
- «Выход» в трее не замораживает окно на время остановки.
- В трее страница больше не опрашивает Ashgate каждые 3 секунды, а
  `schtasks.exe` не запускается раз в минуту: автозапуск читается при
  открытии настроек.
- У `ashgate.exe` есть сведения о версии (VERSIONINFO).

## 0.9.2

Утечки DNS. dnsleaktest в браузере с правилом VLESS показывал рядом с
Cloudflare резолвер провайдера.

- Утечка: собственный запрос браузера уходил через туннель, но если ответ
  задерживался (DNS Xray при сбое DoH вообще не отвечает), Chromium-браузеры
  (Opera, Chrome, Edge, приложения на Electron) переспрашивали службу DNS
  Windows, а она шла напрямую к провайдеру. Так же — `getaddrinfo` всех
  программ. Теперь запросы `svchost.exe` идут через прокси: выбранный или
  прокси первого правила, VLESS в первую очередь. Напрямую остаются зоны
  `.ru`, `.рф`, `.su`, исключения, локальные имена и обратные запросы частных
  адресов. Включено по умолчанию, выключается в настройках («DNS Windows
  через туннель»). Старый `includeSystemResolver` больше не читается.
- Утечка: DNS-пакет, чью программу не удалось узнать за 50 мс (или сразу,
  когда в очереди уже 256 пакетов), уходил напрямую. Теперь он идёт так же,
  как запросы службы DNS Windows.
- Утечка: новый DNS-сокет приложения с правилом мог занять порт, который
  только что закрыла программа без правила. Пока событие о новом сокете не
  пришло, запрос считался запросом той программы и уходил напрямую. Для DNS
  закрытые сокеты больше не учитываются: запрос ждёт события, а без него
  идёт через туннель.
- Утечка: DNS к link-local серверу (`fe80::…`, `169.254.…`, так роутер с
  IPv6 часто раздаёт себя) шёл мимо перехвата.
- Утечка: DNS по TCP приложения с правилом SOCKS5 или HTTP уходил к серверу,
  который выбрало приложение (DNS провайдера), через прокси. Теперь — на
  серверы из настроек, как UDP.
- Утечка: сам Ashgate узнавал адрес VLESS-, SOCKS5- и HTTP-сервера и хост
  подписки у DNS провайдера (каждые 30 минут и при каждом подключении к
  серверу с именем). Теперь через DoH по IP, с кэшем `dnscache.json`.
- Зоны `.ru`, `.рф` и `.su` идут напрямую у правил VLESS, как исключения:
  российские сайты видят настоящий адрес и получают местные ответы CDN.
- Прежний обход через «Системный резолвер» с VLESS ломал исключения: их
  разрешение шло по кругу svchost → Ashgate → Xray → svchost до таймаута.
- DNS, который прокси не смог передать, сразу получает SERVFAIL, а не
  молчание.
- У VLESS порт 53 всегда отвечает DNS Xray, и в режиме «как выбрало
  приложение»: роутер пользователя из VPS недоступен. Запросы HTTPS, SRV,
  TXT, MX через туннель получают ответ, а не отказ.
- В windows-e2e: проверка `getaddrinfo` теперь падает при утечке (раньше
  только записывала её), новые проверки Edge с работающим и упавшим DoH,
  DNS к link-local серверу, 300 запросов сразу, DNS при упавших серверах и
  VLESS-сервер с именем.

## 0.9.1

Исправления после сквозной проверки на Windows (GitHub Actions, windows-latest).

- Утечка: последние пакеты проксированного TCP-соединения (FIN, ACK,
  keepalive, повторы) уходили напрямую с настоящим адресом, если релей уже
  закрылся, а приложение успело выйти. Теперь они отбрасываются; новое
  соединение с того же порта решается заново. То же после перезапуска
  перехвата (например, после падения): пакет посреди соединения, у которого
  уже нет процесса, больше не уходит напрямую. Сопоставление закрытого
  соединения живёт ещё 10 секунд, чтобы последние FIN и ACK обеих сторон
  дошли и сокет приложения закрылся, а не висел полузакрытым.
- Утечка: WebView2 сохранял введённые в диалоге прокси ссылки vless://,
  UUID, ключи, логины и адрес подписки в историю форм своего профиля
  (`%LocalAppData%\Ashgate\WebView2`, читается без прав администратора);
  `autocomplete="off"` он игнорирует. Автозаполнение и сохранение паролей
  в WebView2 выключены.
- Токен окна попадал в дисковый кэш WebView2 через адреса значков
  приложений. Значки больше не кэшируются на диске.
- `%ProgramData%\Ashgate` (и `config.json` с паролями и ключами VLESS)
  читали все пользователи компьютера. Теперь только SYSTEM, администраторы
  и пользователь, который запускает Ashgate; старые файлы получают новые
  права при первом запуске.
- Драйвер WinDivert не выгружался: файл `WinDivert64.sys` оставался занят,
  удаление оставляло папку в `Program Files` и службу драйвера, а повторная
  установка требовала перезагрузки. Ashgate останавливает драйвер после
  «Стоп», при выходе, после падения (сторож kill switch) и при удалении —
  только свою копию.
- «Запустить» сообщал «работает» раньше, чем снимались правила kill switch
  в брандмауэре: около двух секунд приложения оставались без сети.
- Удаление теперь стирает профиль WebView2 в `%LocalAppData%\Ashgate`.
- Без WebView2 Runtime окно с объяснением закрывалось сразу.
- Подсказка «Локальный порт не задан…» в списке прокси обрезалась на
  полуслове, теперь с многоточием.
- «Вставить vless://» и проверка буфера при первом запуске вызывали
  запрос WebView2 «…хочет видеть текст и изображения, скопированные в буфер
  обмена» — при каждом запуске заново (порт окна каждый раз новый). Причина —
  ошибка в go-webview2 (тип разрешения читался по значению, а не по
  указателю); Ashgate собирается с исправленной копией в
  `third_party/go-webview2`.
- Диалог «Добавить приложение» терял введённый путь и фокус, когда в фоне
  приходил список запущенных и установленных программ.
- `/api/state` сообщает число горутин (для проверки утечек в CI); окно его
  не показывает.

## 0.9.0

Защита и маскировка: подписки 3x-ui с переключением серверов, исключения,
DNS через туннель. (0.8.x — номера ветки Ashgate_Beta, здесь пропущены.)

- Локальный прокси моста: свой вход Ashgate на 127.0.0.1 со случайным портом
  и случайным логином при каждом запуске. Опубликованный порт для других
  программ — по желанию и всегда с логином (окно придумывает его, если поля
  пусты). UDP ASSOCIATE выключен на всех SOCKS5: UDP правил Ashgate идёт в
  Xray внутри процесса, локального UDP-порта больше нет.
- Подписка 3x-ui — новый тип прокси. Все её серверы — одна группа: XHTTP
  основной, RAW запасной, дальше остальные. Обновление при добавлении, по
  кнопке и раз в сутки ±10 %; через туннель, если он работает, иначе один раз
  напрямую за 15 с; при ошибке одна повторная попытка через 30 минут; не
  больше одного обновления сразу; плохой ответ оставляет прежний список.
  Если активный сервер в новом списке остался, переподключения нет. Адрес и
  ссылки хранятся зашифрованными (DPAPI) и не пишутся в журнал.
- Переключение серверов подписки: проверка `generate_204` только через
  туннель раз в 60 с ±20 %; две неудачи или 15 с без ответа — следующий
  сервер; если отказали все, попытки реже (экспоненциально, с разбросом); не
  больше двух новых рукопожатий к одному серверу сразу; возврат на основной
  после двух удачных проверок раз в 10 минут, не чаще раза в 5 минут. Kill
  switch при переключении не снимается. В карточке — активный сервер и
  причина переключения.
- Исключения: глобальный список доменов, которые идут напрямую даже при
  правиле через VLESS (маршрутизация Xray по имени). Стартовый список —
  Госуслуги, ФНС, крупные банки, Яндекс, VK, MAX; правится в настройках.
- DNS приложений с правилом VLESS — через DNS Xray: DoH через туннель, домены
  из исключений — системным DNS. Запросы к DNS роутера больше не обходят
  туннель при «Не проксировать частные сети».
- Отпечаток браузера по умолчанию — firefox; `randomized` заменяется на
  firefox; при повторах и переключениях отпечаток и SNI не меняются.

## 0.7.7

Исправления после проверки ошибок, утечек и производительности.

- Добавление прокси падало с «Имя прокси: буквы, цифры, точка, _ или -»:
  имя из `#` ссылки теряло всё, кроме латиницы (русское или из эмодзи
  становилось пустым), а сервер принимал только `[A-Za-z0-9_.-]`. Теперь
  имя может быть на любом алфавите и с пробелами, пустое имя задаётся само
  («VLESS 203.0.113.10»), повтор получает « 2». Ошибки имени и адреса
  показываются под полем, а не всплывающим сообщением.
- После отклонённого сохранения прокси оставался в списке, и повторная
  попытка добавляла его второй раз — «Имя прокси уже занято», даже с
  исправленным именем. Теперь неудачное сохранение возвращает всё как было.
- Переименование прокси, который выбран в приложениях, группах или для
  системного резолвера, больше не падает с «прокси нет в списке».
- «Проверить» для VLESS сообщал «работает, 1 мс», даже когда сервер
  выключен или ключ неверный: локальный SOCKS5 Xray отвечает раньше, чем
  связывается с сервером. Теперь проверка ждёт ответ через туннель и
  объясняет причину по-русски.
- Неизвестный отпечаток браузера (`fp=`) — понятная ошибка.
- Приёмник движка (`relay`) может быть только на 127.0.0.0/8 и `[::1]`,
  иначе к нему можно было бы подключиться из сети.
- Адрес прокси-сервера больше не запрашивается у системного DNS каждую
  минуту (заметный шаблон вне туннеля): раз в 30 минут и сразу после
  изменения прокси.
- Окно в трее больше не сканирует все процессы каждые 3 секунды; файл целей
  kill switch пишется только при изменении; сопоставление правил с
  процессами без лишних выделений памяти.

## 0.7.6

VLESS RAW (TCP) + REALITY + XTLS Vision с серверами Xray v26.

- Встроенный Xray-core обновлён с 25.8.3 до v26.10.31 (последний стабильный).
  В Xray 26 изменился Vision, а серверы v26 могут отклонять клиентов старше
  26.3.27, поэтому RAW + REALITY + Vision не подключался, а XHTTP (без
  Vision) работал. Для сборки нужен Go 1.27.
- TLS: Xray 26 удалил `allowInsecure`. Ссылки с отпечатком сертификата
  `pcs` (pinnedPeerCertSha256) теперь поддерживаются; ссылка только с
  `insecure=1` даёт понятную ошибку вместо моста, который не запускается.
- Ошибка проверки сертификата сервера объясняется по-русски (для REALITY —
  ключ, short id и SNI; для TLS — сертификат).

## 0.7.5

VLESS со ссылками RAW (TCP) + REALITY + XTLS Vision из 3x-ui.

- Транспорт `tcp`/`raw` уходит в Xray как `raw` (с `rawSettings` для
  headerType). В config.json остаётся `tcp`, старые файлы читаются как раньше.
- Неизвестный транспорт в ссылке — понятная ошибка со списком поддерживаемых
  (tcp/raw, xhttp, ws, grpc, httpupgrade). Неизвестный flow на TCP тоже
  ошибка: раньше он молча отбрасывался, и сервер, требующий Vision,

  На главной видно, что заблокировано и для каких правил exe не найден.
- Следующие фрагменты отброшенного фрагментированного пакета тоже
  отбрасываются, а не уходят напрямую.
- Дескрипторы процессов из списка приложений больше не утекают и закрываются
  при остановке перехвата.

Исправления ошибок, безопасности и отзывчивости окна:

- Локальный API окна принимает запросы только с секретным ключом, который
  окно получает при запуске, и только по адресу 127.0.0.1. Раньше любая
  веб-страница или программа на компьютере могла менять конфигурацию
  процесса с правами администратора.
- Windows повторно выдаёт номера процессов. Ashgate больше не путает новую
  программу со старой, у которой был тот же PID: правило применяется к
  настоящему владельцу соединения.
- Кэши процессов, сокетов и прямых соединений больше не растут без предела
  при долгой работе.
- SOCKS5 и HTTP CONNECT: молчащий прокси больше не вешает соединение и
  «Проверить» навсегда — ответ ждётся до таймаута.
- UDP через недоступный SOCKS5 не открывает новую ассоциацию и не пишет
  ошибку на каждый пакет: повтор не чаще раза в 3 секунды. DNS через
  HTTP-прокси идёт параллельно.
- Первое соединение программы начинается быстрее: пакет, ждущий события о
  владельце сокета, проверяется каждые 15 мс, а не держится 50 мс.
- Трафик TCP в окне растёт во время передачи, а не после закрытия соединения.
- Журнал не опрашивает размер файла на каждую строку.
- Окно не перерисовывает кнопки и таблицы, если ничего не изменилось: клики
  по «Старт/Стоп», строкам и меню больше не теряются, выделение текста в
  журнале сохраняется, перетаскивание правил работает надёжно. Журнал
  передаётся, только когда в нём появились новые строки; скрытое окно
  опрашивается реже.
- Выбранная строка журнала не «уезжает» при новых событиях.
- В диалоге приложения выбранный прокси не сбрасывается при поиске или
  смене действия. В списке запущенных программ видны их значки.
- «chrome» в правиле значит chrome.exe.
- DNS-серверы сохраняются после окончания ввода, а не на каждую букву;
  «1.1.1.1» дополняется до «1.1.1.1:53». Имя хоста вместо IP окно не
  сохраняет: движок его всё равно игнорировал.
