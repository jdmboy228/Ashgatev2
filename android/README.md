# Ashgate для Android

Минимальное приложение: туннель только для выбранных приложений.

- **Профили.** VLESS через XHTTP (ссылка `vless://` или адрес подписки 3x-ui: каждый её
  XHTTP-сервер становится профилем) и обычный прокси SOCKS5 или HTTP.
- **Приложения.** Через туннель идут только отмеченные приложения
  (`VpnService.Builder.addAllowedApplication`). Без отмеченных приложений туннель не включается.
- **Россия напрямую.** Как на компьютере: `.ru`, `.su`, `.рф`, список российских сервисов,
  `geosite:category-ru` и `geoip:ru` идут напрямую, остальное через профиль.
- **Без утечек.** DNS отмеченных приложений отвечает Xray и спрашивает серверы через туннель;
  IPv4 и IPv6 целиком уходят в TUN; локального порта SOCKS или HTTP нет: Xray читает TUN сам.
- **Секреты** лежат только на устройстве, в `EncryptedSharedPreferences`; резервные копии
  выключены.

## Устройство

- `ashgate-src/internal/mobilecfg` — профили и документ Xray (без Xray, с тестами).
- `ashgate-src/mobile` — ядро для `gomobile bind`: разбор ссылок и запуск Xray на TUN.
- `android/` — Kotlin: `TunnelService` (VpnService), три экрана, `Store`.

## Сборка

Только в GitHub Actions: workflow `android` (`.github/workflows/android.yml`) запускает тесты,
собирает AAR и APK и выкладывает APK артефактом `ashgate-android-apk`. Android SDK, NDK и Gradle
на сервер разработки не ставятся.

APK отладочный и подписан ключом, который создаётся при каждой сборке: новую сборку нельзя
поставить поверх старой, старую нужно удалить (профили при этом стираются).

## Ограничения

- Имя сервера VLESS или прокси узнаётся системным DNS, мимо туннеля.
- Через HTTP-прокси UDP не ходит и отбрасывается; через SOCKS5 — если сервер умеет UDP.
- Подписка читается один раз, при добавлении; сама не обновляется.
- Изменения профиля и списка приложений переподключают работающий туннель.
